# Decisions — MUTTER android

- **2026-08-21** (Android) — The app records why a hold failed, readable in Settings → Recent activity. Every failure looks identical from outside — one short buzz — whether the microphone was refused, Android muted it, the model would not load, or injection was rejected. Telling them apart needed a notification (POST_NOTIFICATIONS may be denied, so its absence proves nothing) or a cable, and three releases went out guessing between those branches. `Diagnostics` keeps the last 60 events in filesDir; Settings shows them newest first. What was ruled out while chasing a v0.8.1 failure that never reproduced: capture. A real hold driven inside the real accessibility-service process — background, which an instrumentation process never is — promotes the FGS (`Background started FGS: Allowed`), starts the mic and reads audio at 37 ms. Companion rule for tests: a fixture must never name the fallback model by hand. `keeps_the_old_model_while_the_preferred_one_is_incomplete` hard-coded `DISTIL_SMALL_EN` as "the previous model", so promoting it to preferred turned the fixture into the real model and `deleteRecursively()` wiped it mid-suite; every later test then skipped on `assumeTrue` and the run still reported success. Fixtures derive from `KNOWN.first { it !== PREFERRED }`, and a failed restore is an assertion, not a silent `renameTo`.
- **2026-08-21** (Android) — A model directory is deleted only after its replacement is verified on disk, and the app fetches the replacement itself. v0.7.0 shipped a new model and pruned the old one on service connect, before anything had been downloaded: every install lost its only model and dictation stopped, behind a 620 MB download the user had to find and start by hand. The rule is structural now, not a convention — `ModelPolicy.prunable` returns nothing until the preferred model is complete, `pruneSupersededModels` is its only caller, and both are unit-tested. `SttModel` describes a *list* of models (`KNOWN`, preferred first) and `SttEngine` resolves at load time, so an install keeps dictating on the previous model while the new one downloads; a spec with no recorded hashes is load-only and never fetched. `ModelBootstrap` does the fetch on an unmetered network with progress in the shade, waits on a `NetworkCallback` when metered, and broadcasts `ACTION_MODEL_READY`. Wizard and bootstrap share a `Mutex`: two writers on one `.part` produce a size-correct, corrupt file. A storage shortfall is reported, never solved by deleting the working model. Gotcha: the VAD ships *inside* each model directory, so `VadSegmenter` takes a path provider and resolves per `load()` — a path captured at construction points into the directory pruning later deletes, and the post-download reload drops silently into degraded RMS. Verified as a real v0.7.0 → v0.8.0 upgrade on-device — v0.7.0 removed `distil-small.en` on connect, v0.8.0 kept it (`nothing safe to prune`) and fetched parakeet unattended.
- **2026-08-21** (Android) — A refused foreground promotion must not abort the hold. Reverts the v0.7.0 decision to make `promoteToForeground()` fatal: through v0.6.0 the failure was swallowed and dictation still worked, so making it fatal turned one bad phone state into "every press just buzzes". Promotion is still attempted first — it is what keeps Android from feeding the process silence — but capture proceeds either way, and the blocked-microphone notification moved to `AudioRecorder`'s `isClientSilenced()` probe so it fires only when the framework confirms zeros. `AudioRecorder.start` retries once with a fresh track: the prepared AudioRecord is held open between holds and the framework can invalidate it while idle, which surfaces nowhere but `startRecording()`.
- **2026-08-20** (Android) — Model = NVIDIA parakeet-tdt-0.6b-v2 INT8, replacing whisper distil-small.en (v0.7.0). Measured on 250 LibriSpeech test-clean utterances cut to 3–8 s (one sentence at a time, as used) and on an arm64 Android 15 device: WER 4.06% → 1.64%, sentences needing no correction 67.6% → 83.2%, decode of a 7.4 s clip 612 ms → 186 ms, peak PSS 657 MB → 819 MB, disk 291 MB → 661 MB. Paired bootstrap vs distil-small.en −2.42pp CI[−3.23,−1.63]; vs parakeet-tdt-110m −0.75pp CI[−1.22,−0.28]. Chose accuracy over the 162 MB: the phone already carried the 657 MB version, and clean-sentence rate is what a dictation user feels. **parakeet-tdt-110m is the documented fallback** (2.39%, 331 MB, 82 ms) if resident size ever bites — but its int8 files are not on HuggingFace, so it needs the GitHub tarball or a hash-verified mirror. Structural consequence: a transducer has no fixed encoder window, so chunking is now for streaming only, not correctness — Whisper padded every chunk to 30 s, which is where the speed went. NPU is not reachable: sherpa-onnx ships no QNN Android AAR (Rockchip only) and its QNN models are Moonshine and a streaming Nemotron, so Snapdragon stays on CPU.
- **2026-08-20** (Android) — Foreground service must start **before** AudioRecord, not after. Root cause of "the first ~500 ms is missing": Android does not error when a background app records, it hands back silence, and an accessibility service with no UI on top counts as background. The old order started the mic and promoted afterwards, so every hold captured zeros until the FGS registered. The bug was invisible because silence is indistinguishable from a quiet room — capture now logs time-to-first-non-silent-window and `isClientSilenced()`, and a failed promotion (usually a revoked battery-optimisation exemption) is logged but never aborts the hold — see 2026-08-21. AudioRecorder is one reused instance: `prepare()` opens the HAL input, `start()` only leaves standby. Holding it prepared between holds does **not** register as recording — `dumpsys audio` shows `rec start`/`rec stop` bracketing only real holds, so no privacy indicator and no battery cost while idle. Source is VOICE_RECOGNITION (no AGC / call-tuned NS) with a MIC fallback. Gotcha: this path cannot be tested synthetically — `adb shell input keyevent` bypasses accessibility key filtering, the same way synthetic fn events are useless on macOS.
- **2026-06-11** (Android) — Margo design language (v0.6.0). Tokens copied from Margo `design/DESIGN_TOKENS.md` — one design language across personal apps. Intercept toggle is a `ToggleButton` text pill, not SwitchCompat: SwitchCompat thumb metrics clip against custom tracks, and Margo's toggle is a text pill anyway. Gotcha: `fitsSystemWindows` *replaces* root padding with insets — gutters live one level below the root. Icon: vector foreground sized to the 66/108 adaptive safe zone; density PNGs deleted because qualified rasters shadow unqualified vector drawables.
- **2026-06-11** (Android) — Never-drop pipeline (v0.5.0). Root cause of "buzz, nothing written": failed `ACTION_PASTE` → haptic → end-of-hold clipboard *restore* overwrote the transcript 200 ms later. Now: paste → `ACTION_SET_TEXT` splice at cursor → failed chunks accumulate per-hold and `finish()` puts THEM on the clipboard + notification (restore skipped). Capture decoupled from drain: `capturing` flag only; a DOWN during a slow transcription starts a new hold immediately (per-hold `Hold` session rides the FIFO worker — no cross-talk). Engine failure persists chunk to `filesDir/pending/*.wav` + notification; `WhisperEngine.transcribe` `@Synchronized` + nullable (release-mid-decode was a native-crash window; null = failed ≠ "" = heard nothing). Phrase blacklist + `EnergyGate.isSilent` retired — chunks are VAD-confirmed speech, the blacklist ate real "okay"/"thank you"; `Sanitizer.collapseRepeats` bounds repeat-loops instead. Degraded mode (VAD model missing): per-window RMS stands in, so silent holds emit nothing.
- **2026-06-08** (Android) — Unbounded-hold dictation via streaming VAD segmentation. Replaced the 60 s capture cap + 30 s soft-cap warning buzz with: `AudioRecorder` streams 512-sample (32 ms) windows → `VadSegmenter` (Silero VAD `Vad.compute()` per window, ≥0.5 = speech) → `AdaptiveEndpointer` cuts chunks; each cut transcribes immediately on the FIFO `worker` (streaming — text appears mid-hold). Why: sherpa-onnx whisper has a hard 30 s encoder window and does no long-form chunking, so anything past ~30 s was lost — the buzz was the 30 s soft cap firing. Adaptive cut: needs 4 s *speech* before any cut, then silence threshold ramps 500→300→200 ms as *total* chunk grows (7 s, 15 s), hard emergency cut at 25 s. 25 s is total-duration (not speech) specifically to guarantee every chunk < Whisper's 30 s window. VAD loads from file via `Vad(config=…)` with null AssetManager (bytecode-confirmed `newFromFile` path). `silero_vad.onnx` (643854 B) added to `ModelDownloader`. Endpointer is pure/unit-tested (7 spec tests + 4 stress); 41 tests pass, release builds under R8.
- **2026-06-08** (Android) — Daily 5 a.m. recognizer recycle. One inexact `AlarmManager` alarm (`DailyRecycler`) → `engine.release()` + `engine.load()` (re-warms) on `modelExec`, only when IDLE. Why: the accessibility-service process never restarts on its own, so the native sherpa recognizer's heap fragments over long uptime. Recycle bounds it while staying hot; re-armed in `onServiceConnected` so it survives reboots without a BOOT receiver. Per-utterance state already resets (fresh stream per transcribe) — daily recycle is purely a native-heap-floor measure, not a correctness fix.
